# Credit-Scoring-Classification-Metrics-from-Scratch
Цей проєкт присвячений створенню та валідації моделей бінарної класифікації для оцінки ризиків у банківському кредитному скорингу. Головна особливість проєкту полягає в тому, що всі ключові метрики якості (Accuracy, Precision, Recall, F1-Score) реалізовані власноруч з нуля на Python та NumPy без використання готових бібліотечних функцій на кшталт sklearn.metrics
# Головна мета: 
Створити модель яка буде Прогнозувати чи видавати кредит клієнту на основі його даних та спираючись на метрики обрати яких клієнтів ми будемо одобрювати

# Основний Функціонал:
Завантаження та аналіз даних: робота з синтетичним датасетом кредитних історій (credit_scoring_dataset.csv).
Підготовка даних: поділ вибірки на тренувальну та тестову за допомогою train_test_split.
Навчання моделі: використання алгоритму логістичної регресії (LogisticRegression з scikit-learn).
Власноруч написані метрики оцінки якості:
accuracy() — розрахунок загальної точності класифікації.
precision() — розрахунок точності моделі для позитивного класу (схвалення кредиту).
recall() — розрахунок повноти виявлення надійних позичальників.
f1() — розрахунок гармонійного середнього між Precision та Recall.

# Структура Датасету
Датасет (credit_scoring_dataset.csv) містить 2000 записів (рядків) та 16 числових колонки (15 ознак та 1 цільову змінну). Усі дані очищені від пропусків та категоріальних текстових значень, що дозволяє одразу передавати їх у моделі машинного навчання без додаткового кодування

## Приклад коду (реалізація метрик)

Нижче наведено код реалізації власних метрик, розроблених у проєкті:

```python
import numpy as np


# 1. Accuracy (Точність)
def accuracy(y_true, y_pred):
  y_true = np.array(y_true)
  y_pred = np.array(y_pred)
  acc = 0
  for i in range(y_true.shape[0]):
    if y_true[i] == y_pred[i]:
      acc += 1
  return acc / y_true.shape[0]


# 2. Precision (Точність позитивного класу)
def precision(y_true, y_pred):
  y_true = np.array(y_true)
  y_pred = np.array(y_pred)
  tp = 0
  fp = 0
  for i in range(y_true.shape[0]):
    if (y_true[i] == 1) & (y_pred[i] == 1):
      tp += 1
    elif (y_true[i] == 0) & (y_pred[i] == 1):
      fp += 1
  if (tp + fp) == 0:
    return 0
  return tp / (tp + fp)


# 3. Recall (Повнота)
def recall(y_true, y_pred):
  y_true = np.array(y_true)
  y_pred = np.array(y_pred)
  tp = 0
  fn = 0
  for i in range(y_true.shape[0]):
    if (y_true[i] == 1) & (y_pred[i] == 1):
      tp += 1
    elif (y_true[i] == 1) & (y_pred[i] == 0):
      fn += 1
  if (tp + fn) == 0:
    return 0
  return tp / (tp + fn)


# 4. F1-Score
def f1(y_true, y_pred):
  p = precision(y_true, y_pred)
  r = recall(y_true, y_pred)
  if (p + r) == 0:
    return 0
  return 2 * p * r / (p + r)
```
# Результати оцінки моделі
Під час тестування моделі на тестовій вибірці було отримано такі збалансовані результати:
Accuracy: ~0.747
Precision: ~0.747
Recall: ~0.929
F1-Score: ~0.828

# Вибір стратегії банку

Остаточний вибір залежить від бізнес-цілей:

Мінімізувати ризик (менше False Positive): максимізуємо Precision. Банк схвалює лише тих, у кому впевнений, тож неповернених кредитів менше, але частина надійних клієнтів отримає відмову (більше False Negative). Не втрачати клієнтів (менше False Negative): максимізуємо Recall. Банк схвалює більше заявок і заробляє на більшій кількості клієнтів, але зростає частка ризикових кредитів (більше False Positive). Компроміс: орієнтуємось на F1.

У реальному скорингу False Positive зазвичай коштує значно дорожче за False Negative, тому часто обирають вищий поріг, а отже вищу precision.

# Висновок

У проєкті побудовано модель логістичної регресії для прогнозування схвалення кредиту, а метрики якості (Accuracy, Precision, Recall, F1) реалізовано вручну на NumPy без sklearn.metrics.

Результати на тестовій вибірці:

Recall ≈ 0.929 — модель знаходить понад 92% надійних позичальників, тобто рідко відмовляє хорошим клієнтам;
Precision ≈ 0.747 — приблизно кожен четвертий схвалений кредит отримує ненадійний клієнт, і це головна слабкість моделі;
Accuracy ≈ 0.747 — загальна частка правильних рішень;
F1 ≈ 0.828 — загальний баланс прийнятний, але він забезпечений переважно високим Recall.

Модель схильна до надмірного схвалення: вона віддає перевагу тому, щоб не втратити клієнта, ціною більшої кількості ризикових кредитів. Це підходить банку, який орієнтований на зростання кількості клієнтів і готовий приймати вищий ризик. Якщо ж пріоритет — мінімізація збитків від неповернення, модель у поточному вигляді потребує доопрацювання, насамперед підвищення порогу класифікації для збільшення Precision.
